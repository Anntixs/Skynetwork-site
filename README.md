# SkyNetwork — сайт сети

Сайт сети виртуальной авиации SkyNetwork: регистрация и CID, карта и списки онлайна, планы полёта для SkyPilot, мероприятия, бронирование позиций, новости, обучение диспетчеров, поддержка, открытый API и закрытый раздел управления для команды. ASP.NET Core 8 (Razor Pages), SQLite.

## Язык и тема

Сайт по умолчанию на английском. В шапке есть переключатель языка (English / Русский): выбор хранится в cookie `lang` на год. Все тексты написаны на английском в страницах, русский перевод лежит в `Localization/Ru.cs`. Тест `LocalizationTests` проверяет, что у каждого текста есть перевод и что в переводе сохранены подстановки `{0}`.

Там же переключатель светлой и тёмной темы. Без выбора сайт следует системной теме, выбор хранится в cookie `theme`. Подложка карты меняется вместе с темой (CARTO Light / Dark Matter).

## Разделы

**Для всех**
- **Главная**: кто в эфире, мини-карта, ближайшие мероприятия, новости, первые шаги.
- **Карта**: пилоты по курсу движения, диспетчеры с зонами. Обновляется каждые 15 секунд.
- **Онлайн**: диспетчеры в виде стрипов с частотами, пилоты с маршрутами.
- **Мероприятия**, **Новости**, **Бронирование позиций** (UTC).
- **Профиль участника**: диспетчерский, пилотский и военный рейтинги, часы пилотом и диспетчером, последние подключения.
- **Документация**: как начать, программы (SkyPilot, Network-ATC), рейтинги, правила, API.

**Для участника**
- **Регистрация**: выдаёт CID. Логин и пароль те же, что для подключения к сети.
- **Личный кабинет**: статистика, сессии, последний план.
- **План полёта**: подаётся на сайте, SkyPilot забирает его сам (см. ниже).
- **Обучение**: заявка на следующий рейтинг в любом из трёх направлений (диспетчер, пилот, военный); инструктор отвечает и присваивает рейтинг.
- **Обращения** в поддержку, **настройки** (почта, страна, пароль).

**Управление** (`/staff`) — скрытый раздел. Для всех, кроме команды, его нет: ответ 404 без редиректа на вход, ссылок нигде не видно, `noindex`. Права зависят от рейтинга и ролей:

| Кто | Что может |
|---|---|
| ADM — администратор | всё, включая роли на сайте и любые рейтинги |
| SUP — супервайзер | участники, блокировки с причиной, заметки, онлайн, обращения, бронирования, мероприятия, новости, журнал |
| I1–I3 — инструкторы | заявки на обучение, рейтинги до C3, заметки, онлайн |
| роль «Мероприятия» / «Новости» | только свой раздел |
| роль «Поддержка» | обращения, поиск участников, сброс паролей |
| роль «Обучение» | как у инструктора |

**Рейтинги.** Диспетчерский рейтинг (OBS…ADM) общий с FSD-сервером. Пилотский (P0, PPL, IR, CMEL, ATPL, FI, FE) и военный (M0–M4) хранятся только на сайте. Их выставляют супервайзеры, инструкторы и администраторы в карточке участника или при завершении заявки на обучение.

**Блокировка.** Блокировка ставится с причиной и сроком: 1, 3, 7, 30 или 90 дней, либо навсегда. Заблокированного сразу выбрасывает с сайта. FSD-сервер отключает его в течение 10 секунд и не пускает обратно. При входе участник видит причину и дату окончания. Когда срок выходит, сайт снимает блокировку сам (проверка раз в минуту). Супервайзер не может заблокировать другого супервайзера или администратора.

Каждая страница управления проверяет своё право и без него отвечает 404. Каждое действие — рейтинг, блокировка, роли, сброс пароля, заметка, правка контента — пишется в **журнал действий**.

## Общая база с FSD-сервером

Сайт работает с той же SQLite-базой, что и `skynet-fsd` (параметр `--db`):
- таблица `members` — это таблица аккаунтов сервера, пароли хешируются так же (PBKDF2-SHA256, 200 000 итераций);
- участник, зарегистрированный на сайте, сразу подключается к сети;
- заблокированный на сайте не сможет подключиться;
- рейтинг, выставленный на сайте, действует в сети.

Остальные таблицы — собственные таблицы сайта.

Онлайн сайт берёт из `/data.json` сервера (HTTP-порт `skynet-fsd`) и по нему ведёт журнал подключений — отсюда часы и статистика.

## Запуск

```sh
# сервер сети
skynet-fsd --db /srv/skynetwork/skynetwork.db --port 6809 --http-port 8080
# первый администратор
skynet-admin --db /srv/skynetwork/skynetwork.db adduser 1 "Имя Фамилия" пароль ADM
# сайт
dotnet run --project src/SkyNetwork.Site -- --Site:Database=/srv/skynetwork/skynetwork.db
```

Настройки — в `appsettings.json`, раздел `Site`; любую можно передать аргументом `--Site:Имя=значение`:

| Настройка | По умолчанию | |
|---|---|---|
| `Database` | `skynetwork.db` | файл базы, общий с `skynet-fsd` |
| `DataFeedUrl` | `http://127.0.0.1:8080/data.json` | поток данных FSD-сервера; пусто — без онлайна |
| `FsdHost`, `FsdPort` | `127.0.0.1`, `6809` | адрес сервера на страницах «Как начать» |
| `FirstCid` | `1` | CID первого зарегистрированного; дальше по порядку: 1, 2, 3… |
| `TileLayers` | см. `SiteOptions.DefaultTileLayers` | слои карты `light`, `light-labels`, `dark`, `dark-labels`: у каждого список источников `{z}/{x}/{y}` по порядку; сайт скачивает их сам |
| `TileCache` | папка `tiles` рядом с базой | кэш подложки карты, обновляется раз в неделю |
| `BehindProxy` | `false` | за nginx: доверять `X-Forwarded-For/Proto` |
| `AuthAttemptsPerMinute` | `10` | попыток входа и регистрации в минуту с одного адреса |

Сайт слушает `http://0.0.0.0:8000` (`Urls` в `appsettings.json`), это адрес по умолчанию в SkyPilot. В продакшене поставьте перед ним nginx с HTTPS и включите `BehindProxy`.

## Установка на сервер

Готовые файлы лежат в `deploy/`: службы systemd для FSD-сервера, голосового сервера и сайта, конфиг nginx. Пример для Ubuntu 22.04/24.04, домен `example.com`:

```sh
# пакеты
sudo apt update
sudo apt install -y git cmake g++ libssl-dev libsqlite3-dev dotnet-sdk-8.0 nginx certbot python3-certbot-nginx
sudo useradd --system --home /var/lib/skynetwork --create-home skynetwork

# FSD-сервер
git clone https://github.com/Anntixs/Skynetwork-fsd.git ~/Skynetwork-fsd
cmake -S ~/Skynetwork-fsd -B ~/Skynetwork-fsd/build && cmake --build ~/Skynetwork-fsd/build -j
sudo install -D -t /opt/skynetwork/fsd ~/Skynetwork-fsd/build/skynet-fsd ~/Skynetwork-fsd/build/skynet-admin

# голосовой сервер
git clone https://github.com/Anntixs/Skynetwork-voice.git ~/Skynetwork-voice
cmake -S ~/Skynetwork-voice -B ~/Skynetwork-voice/build && cmake --build ~/Skynetwork-voice/build -j
sudo install -D -t /opt/skynetwork/voice ~/Skynetwork-voice/build/skynet-voice

# сайт
git clone https://github.com/Anntixs/Skynetwork-site.git ~/Skynetwork-site
dotnet publish ~/Skynetwork-site/src/SkyNetwork.Site -c Release -o ~/site-build
sudo mkdir -p /opt/skynetwork/site && sudo cp -r ~/site-build/. /opt/skynetwork/site/

# службы и nginx (в файлах замените example.com на свой домен)
sudo cp ~/Skynetwork-site/deploy/*.service /etc/systemd/system/
sudo cp ~/Skynetwork-site/deploy/nginx.conf /etc/nginx/sites-available/skynetwork
sudo ln -s /etc/nginx/sites-available/skynetwork /etc/nginx/sites-enabled/
sudo systemctl daemon-reload
sudo systemctl enable --now skynet-fsd skynet-voice skynetwork-site
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d example.com

# порты: сайт (80, 443), FSD (6809/tcp), голос (3782/udp); 8000 и 8080 остаются внутренними
sudo ufw allow OpenSSH && sudo ufw allow 'Nginx Full' && sudo ufw allow 6809/tcp && sudo ufw allow 3782/udp && sudo ufw enable
```

Оба процесса работают от пользователя `skynetwork` с одной базой `/var/lib/skynetwork/skynetwork.db`. Первый зарегистрированный на сайте получает CID 1. Права администратора ему выдаются так:

```sh
sudo -u skynetwork /opt/skynetwork/fsd/skynet-admin --db /var/lib/skynetwork/skynetwork.db rating 1 ADM
```

Обновление FSD-сервера, голосового сервера и сайта одной командой: `sudo bash ~/Skynetwork-site/deploy/update.sh`. Скрипт скачивает свежие версии с GitHub, собирает, перезапускает и проверяет. Если голосового сервера ещё нет, скрипт сам скачает его, установит службу и откроет порт 3782/UDP. Логи: `journalctl -u skynetwork-site -f`.

## API

Открытый JSON API, только чтение, CORS разрешён. Описание — на странице `/developers`.

| Запрос | Что возвращает |
|---|---|
| `GET /api/v1/status` | название сети, адрес FSD, состояние данных |
| `GET /api/v1/online` | пилоты и диспетчеры в эфире |
| `GET /api/v1/stats` | участники, онлайн, подключения |
| `GET /api/v1/members/{cid}`, `…/sessions` | профиль и подключения участника |
| `GET /api/v1/events`, `/events/{id}`, `/bookings`, `/news` | мероприятия, бронирования, новости |
| `GET /api/flightplans/latest?cid=` | последний план участника для SkyPilot (формат — `docs/website-api.md` в репозитории SkyPilot) |

SkyPilot открывает `/flightplan?callsign=…` для подачи плана и забирает его из `/api/flightplans/latest`.

## Дизайн

Минималистичный, светлый или тёмный (переключатель в шапке, по умолчанию — как в системе), английский или русский: один акцентный синий, шрифты Manrope, Inter и JetBrains Mono (лежат в `wwwroot/fonts`, лицензия OFL). Живой трафик оформлен как диспетчерские стрипы: цветная кромка по типу позиции, позывной моноширинным шрифтом. Leaflet тоже лежит локально (`wwwroot/lib/leaflet`). Подложку карты (Esri Light Gray или Dark Gray по теме, при недоступности — OpenStreetMap) сайт скачивает сам и отдаёт с адреса `/tiles/…`, поэтому браузеры посетителей обращаются только к сайту.

Карта устроена как радар: по щелчку на борт открывается карточка с планом полёта, маршрутом, линией пути и расчётным временем прибытия; по щелчку на диспетчера или аэропорт — частоты, вылеты и прилёты. Работающие CTR и FSS подсвечивают свой сектор по позывному: сначала подсектор (UUWV_N_CTR — северный сектор Москвы), затем весь FIR, затем верхний сектор из нескольких FIR. Границы секторов всего мира — `wwwroot/data/firs.json` (источник и лицензия — в `firs.LICENSE.txt`), координаты аэропортов — `wwwroot/data/airports.json` (OurAirports, общественное достояние).

План полёта можно загрузить из SimBrief (страница «План полёта», имя пользователя или Pilot ID): сайт забирает последний OFP вместе с точками маршрута и их координатами, и карта рисует маршрут по этим точкам, отмечает следующую точку и считает остаток пути. Планы, поданные без SimBrief, сайт разбирает сам (`Services/NavData.cs`): точки, раскрытые по трассам участки, координаты; из одноимённых точек в разных концах света выбирается та, что ложится в цепочку, а точки с большим крюком и неизвестные элементы пропускаются (они перечислены в карточке). База — открытые данные о точках и трассах (`Nav/fixes.dat.gz`, `Nav/airways.dat.gz`, лицензия и источник в `Nav/LICENSE.txt`) плюс VOR/NDB и аэропорты из OurAirports; вдобавок сайт запоминает каждую точку и отрезок трассы из импортированных планов SimBrief (таблицы `nav_fixes`, `nav_airways`), так что база становится актуальнее с каждым импортом. Разбор доступен и через API: `GET /api/v1/routes/decode?departure=…&destination=…&route=…`. Пройденный путь сайт запоминает сам, пока борт в сети. При приближении к аэропорту карта показывает его схему — ВПП с номерами, рулёжки, перроны, здания, гейты и стоянки — из OpenStreetMap (Overpass API, кэш на диске на 30 дней в папке `airports` рядом с базой). В карточке аэропорта — METAR (Aviation Weather Center).

## Тесты

```sh
dotnet test
# с проверкой совместимости с настоящим сервером:
SKYNET_FSD_BUILD=/путь/к/Skynetwork-fsd/build dotnet test
```

Тесты:
- страницы и 404;
- регистрация, вход, блокировка;
- план полёта и API для SkyPilot;
- бронирования;
- скрытость раздела управления и права каждой страницы;
- повышение рейтинга инструктором;
- разбор потока данных и учёт сессий;
- аккаунты, общие с `skynet-fsd` и `skynet-admin`.
